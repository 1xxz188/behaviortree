## 1. 目标与已确定的实现边界

### 1.1 必须实现的用户需求

1. `Notify` 不再接收手写的事件名称字符串，业务代码使用生成的强类型枚举常量。
2. 编辑器提供独立的“事件枚举”管理入口，支持新增、修改、删除事件。
3. 业务节点的事件依赖只能从已定义事件中选择，禁止自由输入和自动创建未知事件。
4. 画布左上角有半透明、常驻、可折叠的事件列表。点击事件，高亮当前画布上引用该事件的节点。
5. 删除事件时，自动清除整个工程内相应的节点事件配置，而不是只清理当前树。
6. 不做旧字符串事件数据兼容；旧数据明确拒绝，不静默转换或丢弃。
7. 支持为整个事件枚举填写“枚举功能注释”，为每个枚举成员填写“事件项注释（字段注释）”；均支持中文多行文本、修改和清空。
8. 画布左上角标题栏可点击查看枚举功能注释，每个事件行可点击查看该事件项注释；查看注释与点击行主体高亮节点是独立操作。

## 3. 新数据模型与稳定 ID

### 3.1 工程与业务定义

以下为目标模型；新增字段使用这些 JSON 名称。

```go
// model 层：事件 ID 在工程 JSON 中使用固定格式字符串无损存储。
type EventDefinition struct {
    ID          string `json:"id"`                    // 16 位小写十六进制稳定 ID，非零，不供用户编辑。
    Name        string `json:"name"`                  // 界面显示名称，例如“命令变化”。
    CodeName    string `json:"codeName"`              // 枚举成员代码名，例如 CommandChanged。
    Description string `json:"description,omitempty"` // 此枚举成员的字段注释：含义、触发时机和注意事项。
}

// 在现有 Project 上新增：
EventEnumDescription string            `json:"eventEnumDescription,omitempty"` // 整个事件枚举的功能注释。
Events               []EventDefinition `json:"events"`                         // 枚举成员注册表。

// 在现有 Definition 上替换旧 Events 字段：
EventIDs []string `json:"eventIds,omitempty"`
```

前端同步新增 `EventDefinition`、`Project.events`、`Project.eventEnumDescription?: string`、`EventDefinition.description?: string`、`Definition.eventIds`，删除旧 `Definition.events`。TypeScript 可以给 ID 加品牌类型辅助检查，但不能仅依靠类型断言，所有输入边界必须做真实校验。

本次“字段注释”特指 `CommandChanged`、`CombatChanged` 等**枚举成员的注释**，不是为 id/name/codeName 属性另建注释，也不是黑板 Field、节点参数 Parameter 或节点实例 Comment。每个工程仍只有本方案这一份事件枚举，不引入通用多枚举管理系统。

### 3.2 ID 的分配和序列化规则

- 创建时使用浏览器 `crypto.getRandomValues` 生成 8 字节，按字节编码为 16 位小写十六进制；拒绝全零，并通过注册表索引检查冲突，冲突则重试。
- 不使用 `Math.random`、事件名称哈希、数组下标、排序位置或生成时重新分配的序号。
- ID 在创建后不可在普通 UI 中编辑。保存、导出、重新打开、改名、排序、代码生成时保持不变。
- 删除后新建同名事件必须按新事件创建，不主动复用旧 ID；撤销删除则恢复原 ID。
- JSON 只接受 `^[0-9a-f]{16}$` 且不等于 `0000000000000000`。拒绝 JSON 数字、空字符串、非规范长度的数字文本、`0x` 前缀、超长和大写混用，不在读取时偷偷规范化错误 ID。恰好 16 位的纯数字字符串也按十六进制解释，不猜测其十进制含义。
- 前端 ID 始终按字符串处理，禁止转成 JavaScript `number`；Go 在模型校验/生成阶段以 `strconv.ParseUint(id, 16, 64)` 解析成数值。
- 新增 `model.ParseEventID` 等单一解析入口，所有模型路径复用；解析不进入 Notify 热路径。

这里的 JSON 字符串是**稳定身份的序列化格式**，不是手写业务事件名称。业务代码和运行时依赖查找使用数值 `bt.EventID`。

随机 64 位 ID 不构成安全令牌，也不承诺跨所有独立系统数学意义上的绝对无碰撞。当前工程创建和导入合并必须显式检查身份冲突；本任务解决事件规范和误写，不建立抵抗恶意调用者的安全边界。

### 3.3 名称与代码名

`Name` 允许中文，去除首尾空白后不能为空；展示时始终同时提供 `CodeName`，防止相似显示名混淆。显示名称不是匹配事件的主键。

`CodeName` 使用 `^[A-Z][A-Za-z0-9_]{0,79}$`，由生成器添加 `Event` 前缀。例如 `CommandChanged` 生成 `EventCommandChanged`。工程内禁止代码名重复和仅大小写不同的代码名；拒绝会与保留常量或既有生成符号冲突的结果。

必须统一检查最终 Go 包中的标识符冲突，包括业务函数名、参数结构名、黑板访问器以及生成器已有公共声明；不能等到用户编译时才发现 `EventCommandChanged` 已被别的声明占用。能在模型阶段判断的立即报错，依赖展开后符号的在生成器统一符号检查中拒绝。不要用自动加数字后缀掩盖冲突。

改 `Name`、成员 `Description` 或工程 `EventEnumDescription` 不改变事件身份；改 `CodeName` 也不改变 ID，但生成的 Go 常量名会变，原业务调用须修改，不能保留旧名称别名作兼容。

### 3.4 空值和格式严格性

新格式工程 JSON 必须显式包含数组 `events`，无事件时是 `[]`；缺失或 `null` 拒绝。程序化构造的空列表可在 Encode 时规范化为 `[]`，不能输出 `null`。

`eventIds` 可以缺省或是 `[]`，表示无事件依赖；出现时必须是合法 ID 数组，拒绝 `null`、重复 ID 和未知 ID。不要在导入、校验或代码生成中把未知引用静默过滤掉。

现有未连完的树仍允许保存为草稿，但草稿中的事件注册表和事件引用必须有效。**树结构尚未完成与事件身份非法是两类问题，不能混为一谈。**

### 3.5 双层注释的唯一来源、校验与持久化

| 层级 | 唯一数据来源 | 界面文案 | 用途 |
| --- | --- | --- | --- |
| 整个事件枚举 | `Project.eventEnumDescription` | 枚举功能注释 | 说明这一组事件的整体职责、适用范围及共同约定。 |
| 单个枚举成员 | `Project.events[i].description` | 事件项注释（字段注释） | 说明该事件的含义、何时通知、先更新哪些业务状态及特殊注意事项。 |

沿用上一版已规划的成员 `description`，不再并存 `comment`、`fieldComment` 等同义存储字段；整体注释也不能复制到每个事件项或业务定义中。保留既定 Schema 3，不因本次任务书补充可选注释字段再次升版；这不恢复 Schema 2 或旧字符串事件兼容。

两类注释采用相同输入合同：

- 可缺省或为空字符串，表示尚未填写；出现时必须为字符串，`null`、数字、布尔值、数组或对象均拒绝。错误精确定位到 `eventEnumDescription` 或 `events[i].description`。
- 支持中文、换行和段落。统一将 CRLF/CR 转成 LF；全文仅为空格、Tab、换行时规范化为空，其他内容保留缩进和段落，不擅自折叠空白或逐行 trim。
- 规范化后，每条注释上限为 **16 KiB UTF-8 字节**；前端与 Go 使用相同口径，不能用 JavaScript `string.length` 冒充 UTF-8 字节数。拒绝 NUL；超限或非法内容明确报错，不静默截断。整工程仍受现有体积限制。
- Encode/交换导出可省略规范化后的空注释字段；缺省与空字符串的语义签名一致。统一辅助函数处理规范化和校验，生成及版本摘要也调用同一规则；不能修改用户传入的模型对象。
- 工程保存、重新打开、完整工程导入导出、快照、撤销/重做、目录交换和 CLI 均保留两类注释。`blankProject`、`emptyProject`、`model.Example` 等工厂同步处理缺省值；不存在事件时也允许先保存整体注释。

注释是描述信息，不是事件名、ID、参数表达式、脚本或订阅条件。改注释不能新增事件、改变绑定、触发 Notify、重启运行实例或改变控制流；但因生成源码及描述元数据变化，必须标记工程未保存并使产物快照过期。仅打开/关闭说明浮层则没有这些副作用。

## 4. 运行时：强类型枚举与合法事件校验

### 4.1 目标 API

```go
// EventID 标识工程中显式声明的宿主事件，不是事件名称。
type EventID uint64

// InvalidEventID 不代表任何业务事件。
const InvalidEventID EventID = 0

// 保持原 Status 返回值，仅改变事件参数类型。
func (i *Instance[C]) Notify(event EventID) Status
```

删除旧 `Notify(event string)`。同步修改仓库内宿主封装，例如 Room/NPC/Manager 的 Notify 方法，使参数类型贯穿调用链，不允许外层仍收字符串、内部再查表。

目标调用方式：

```go
// 先更新权威业务状态，再通知行为树。
room.UpdateCommand(unitID, command)
room.Notify(unitID, behavior.EventCommandChanged)

// 直接使用实例时：
instance.Notify(behavior.EventCombatChanged)
```

上面 `room` 方法是业务用法示意，不要求框架新增这些业务 API，也不要求改变用户现有 Context/Room 结构。

必须保证以下写法无法作为正常接口继续使用：

```go
instance.Notify("command.changed")
instance.Notify("commnad.changed")
```

**不要改成 `type EventID = string`，也不要采用底层 string 的命名类型作为本方案替代。** 本方案需要字符串调用在编译阶段暴露，不能只给字符串换一个类型名称。

### 4.2 Program 结构

保留现有 Version、Roots、Nodes、Fields、Step、Abort 等字段，将混合 Dependencies 拆开：

```go
// runtime 层，与 model.EventDefinition 分开；ID 已在生成时转换成数值。
type EventDefinition struct {
    ID          EventID // 稳定事件身份。
    Name        string  // 展示名称，供诊断。
    CodeName    string  // 枚举成员代码名。
    Description string  // 当前事件项的字段注释；不参与事件匹配或通知调度。
}

// Program 新增/替换部分：
EventEnumDescription string // 整个事件枚举的功能注释，由工程生成，属于本版本只读描述。
Events            []EventDefinition
FieldDependencies map[string][]int  // 键直接使用黑板字段稳定 ID，不加 field: 前缀。
EventDependencies map[EventID][]int // 键为声明过的事件 ID。
```

移除旧 `Dependencies map[string][]int` 和 `event:`/`field:` 混合解析分支。黑板字段类型及自动通知机制保持不变，只调整 Program 中的静态依赖描述。

`preparedProgram` 保存共享的 `eventByID` 索引；`rootDependencies.events` 改成 `map[EventID]int`。继续复用当前 groups 结构和字段槽位前缀，不要求重新设计 observe、pending、pendingMask、dirty queue。

### 4.3 prepareProgram 必须验证和复制的内容

在 NewInstance/NewRegistry/版本发布与插件校验所复用的程序准备入口完成以下工作：

1. 事件 ID 非零且不重复；事件元数据合法；定义完整纳入当前 Program 的合法集合。
2. 每个 `EventDependencies` 键必须已声明，即使该键的观察者数组为空，也不能绕过检查。
3. 字段依赖必须引用现有字段；两类依赖中的节点索引必须有效且无重复。
4. 深拷贝 Events 切片、两个依赖 map 及其切片，保留整体与成员注释，不能让调用方在发布后修改原切片而改变已发布 Program。`EventEnumDescription` 随 Program 值复制；不在每个 Instance 上再保存一份注释结构。
5. 按现有预处理方式划分入口观察者组，不在每个实例里复制全工程事件定义和完整依赖表。
6. 继续验证 Roots/Nodes 的先序结构和子树范围，不为事件改造放宽既有校验。
7. 程序化直接构造 Program 也校验注释长度和 NUL 等合同。注释校验/规范化仅在准备阶段进行，不加入 Notify、Tick 或依赖索引的热路径。

### 4.4 Notify 的明确行为

保持 `closed`、非 Running、busy 和宿主串行队列的既有生命周期边界。[S2]

| 场景 | 必须行为 |
| --- | --- |
| 当前入口有该事件观察者 | 通过数值 map 查组，调用原 observe 流程；空闲时仍可立即 Tick，busy 时仍合并，禁止重入。 |
| Program 声明了该事件，但当前入口没监听 | 合法空操作，返回当前状态，不执行无关树，不打印“未知事件”错误。 |
| Program 声明了该事件，但全工程暂未引用 | 同样合法；不能因为依赖表没有键就把它判为野生事件。 |
| Running 实例收到 0 或未声明 ID | 拒绝通知，不置 dirty，不推进 Tick，不修改异步结果；通过现有日志接口给出含 ID、版本和实例信息的诊断。 |
| 已关闭或非 Running 实例 | 延续现有早退规则，不因新增校验重新启动或抛出生命周期副作用。 |

未知 ID 的诊断不要写入会使整棵树失败的 `i.err`，不要触发业务 Abort，不要把错误当作正常状态变化。沿用项目现有结构化日志设计，避免为合法事件新增日志分配；异常路径按现有日志控制策略处理，不建立无限增长的“已见错误 ID”集合。

推荐查找顺序：先查当前入口观察者 map；命中即可走既有快路径。未命中再查共享合法事件集合，区分“合法但无人监听”和“未定义”。Program 准备阶段保证观察者表中的 ID 都已声明。

Go 命名数值类型并不是安全意义的封闭枚举：调用者仍可能写数字常量或显式转换。**本方案的约束是字符串误写编译失败，未声明数值运行时拒绝。** 对故意构造的已注册数值，无法判断其是否来自生成常量，不作虚假保证。

### 4.5 不得改变的事件语义

Notify 仍是“宿主状态已变化，请重新评估依赖”的通知，不是事件消息队列、资源锁或异步完成结果。

- 异步操作完成继续使用 `Complete(token, result)`；不新增 `movement.arrived` 一类完成事件来替代 token。
- Condition 可以监听；Running Action 在需要响应状态变化时也可以监听。不要为了获得 Abort 机械地给所有动作重复加依赖。
- Abort 仍由既有控制流重选和生命周期逻辑触发；本任务不改变抢占顺序、拾取权仲裁或任务意图保存策略。
- 外部线程仍须先投递到实例所属串行队列，不能因为事件类型变成数值而并发调用实例。

## 5. 代码生成、产物稳定性和热更

### 5.1 生成位置与形式

在现有 `glue.gen.go` 中生成全部事件常量和 Program 元数据，不增加新目录，不把公共枚举复制进每棵树文件。[S7]

```go
// 工程事件枚举：以下常量用于宿主通知当前工程的行为树。
// 用于本工程 AI 对宿主业务状态变化的重新评估。
// 先更新权威业务状态，再 Notify；异步完成仍使用 Complete。
const (
    // EventCommandChanged 表示“命令变化”。
    // 宿主更新玩家命令及目标后通知；用于重新评估分支。
    // 例如：玩家从采集切换为移动；本事件不携带异步完成结果。
    EventCommandChanged bt.EventID = 0x7d65e20a9143bc01

    // EventCombatChanged 表示“战斗状态变化”。
    // 宿主更新战斗状态后通知。
    EventCombatChanged bt.EventID = 0x8e76f31ba254cd02
)
```

**生成合同：** 整体功能注释放在工程生成的事件常量组上方；每个成员的字段注释放在对应常量紧上方，成员首行仍以完整 Go 常量名开头。不要把用户工程的专用注释写进运行库通用 `bt.EventID` 类型，也不要为显示整体注释另造不兼容的项目级事件类型。

复用生成器的安全行注释输出方式：规范化换行后，为每一行都添加 `// `（包含空格）前缀，不直接拼接原始文本为 Go 源码，不使用用户文本包围的块注释。空注释仅保留自动生成的基础说明，不生成“未填写”占位业务注释；多行、引号、反斜杠、`*/`、`//go:` 等文本都不能变成可执行代码或有效编译指令。

`NewProgram` 同时写入 `EventEnumDescription` 和各成员的 `Description`；所有字符串值使用已有安全字符串字面量输出方式，不用手工补引号。没有成员时不生成空的事件常量组，但整体注释仍必须存入 Program 元数据，保存和再次生成不能丢失。

生成的 `EventDependencies` 使用常量名而非裸数字，提高可读性；值仍是编译期数值，不在运行时解析十六进制或根据名字查事件。

所有事件都生成常量，包括暂未使用的事件。事件依赖仍必须基于展开后的 action/condition 位置收集，支持子树多次引用产生的不同运行槽位。[S6]

### 5.2 稳定排序与版本摘要

新增单一的事件规范化逻辑，供生成器与前端源码过期判断对齐：

- 事件定义按固定格式 ID 排序；单个定义的 eventIds 按 ID 排序后参与语义比较。
- 对输入中的重复 ID 报错，不能借规范化悄悄去重。
- 事件在管理列表中的展示顺序、画布面板的展开/搜索/选中状态，以及注释浮层的打开/关闭/查看对象不参与代码生成摘要。
- ID、CodeName、Name、成员 Description、整体 EventEnumDescription、事件增删、定义引用变化均参与本次产物摘要。两类注释和名称进入生成注释或 Program 元数据，因此编辑保存后使源码/骨架快照过期；这不代表事件身份变化。仅将缺省改为规范化后的空字符串，或 CRLF 改为等价 LF，不制造无意义摘要变化。
- 保留原本对树布局、分类目录、树显示名称等数据的规则，不借此改造扩大其他版本语义。
- 同一有效输入反复生成，文件内容、枚举值和摘要应相同；仅重排 events 或 eventIds，不产生无意义差异。

同步检查 `web/src/generation.ts` 的 `semanticSignature`、`App.vue` 的 semanticRevision/CodeSnapshot/ScaffoldSnapshot，以及后端预览和磁盘源码匹配路径。禁止修改事件后 UI 仍显示旧生成代码“最新”。[S10]

### 5.3 删除和改名后的生成结果

删除事件并完成级联清理后，下一次生成必须同时移除对应常量、Events 定义和 EventDependencies 项，不保留废弃别名或空壳。

删除/修改事件代码名后，仓库内业务代码的旧常量调用必须同步调整并通过真实编译。编辑器不擅自删除用户任意手写 Go 业务代码；其责任是元数据级联清理与重新生成，手写代码的编译错误负责暴露尚未完成的调用修改。

### 5.4 热更与旧版本边界

保留现有完整 Program 发布和版本固定机制，不修改 EndOfRound / CancelAndRestart 的业务含义。[S3]

- 稳定 ID 在不同版本中保持一致，改名/插入/重排不改变老事件的数值。
- 新增/删除事件通过新 Program 生效，不原地修改旧版本的共享合法事件表。两类注释也随完整 Program 固定，更新注释不得反写旧 Program；注释本身不参与 Notify 匹配和状态迁移。
- EndOfRound 下仍运行旧 Program 的实例按旧表判断事件；新版删除的事件在旧实例中仍可能合法，新版新增的事件在旧实例中可能尚未声明。这属于版本固定，不是字符串兼容层。
- CancelAndRestart 按现有时机切换完整版本，并重建/替换当前入口依赖视图；旧 pending 组索引不得错误用于新版本。
- 事件定义变更不能让旧 CallbackToken 或已 Abort 动作重新生效。
- 本次修改 `Program` 和 `Notify` 的公共 API，第一次升级需要重建宿主及插件。检查共享包源码与 APIFingerprint 的计算范围，把新事件类型所在文件纳入；保留旧插件拒绝机制，不绕过契约。[S16]
- 不因工程 schemaVersion 改成 3 就机械修改不相关的插件 manifest 格式版本；按实际协议变化判断，既有 manifest 契约校验仍必须有效。
- Go 常量在编译期绑定。不能承诺“只更新工程 JSON，就能让未重编译宿主引用新的 Go 常量名称”。


## 6. 编辑器：独立“事件枚举”管理入口

### 6.1 页面内容

新增独立组件 `web/src/EventManager.vue`，从主导航和画布事件面板的“管理”按钮进入。它是工程内管理界面，不是要求额外建立一个事件 JSON 文件。

管理页面分为两个明确层级，不把它们合成一个含糊的“说明”输入框：

**枚举整体区域：** 位于成员列表上方，标签为“枚举功能注释”，提供多行输入、当前内容展示及“保存整体注释”操作，绑定 `Project.eventEnumDescription`。允许在尚无事件成员时填写；删除最后一个成员也不自动清空整体注释。整体区域与成员编辑表单分别维护草稿，保存其中一处不得顺带提交另一处未确认的修改。

**成员列表与编辑区域：** 列表至少展示显示名称、代码名/最终 Go 常量名、字段注释摘要或“未填写注释”、引用业务定义数、引用画布节点数。稳定 ID 在详情中只读展示并可复制，不把十六进制 ID 当作列表主标题。

每个成员的新增/编辑表单包含：

| 字段 | 行为 |
| --- | --- |
| 显示名称 | 必填，允许中文。 |
| 枚举代码名 | 必填；即时展示完整常量名，如 `EventCommandChanged`；校验唯一性和符号合法性。 |
| 事件项注释（字段注释） | 可选、多行，绑定该成员的 `description`；引导描述“含义、何时在业务状态更新后 Notify、注意事项”，不得保存成整体注释。 |
| 稳定 ID | 创建时自动分配；编辑时只读。 |
| 引用情况 | 展示定义和树/节点引用，辅助判断改名和删除影响。 |

所有表单编辑先作用于草稿，点击保存后校验并提交一次事务；取消不得污染工程，失败不得部分提交。长期开着的表单必须检测工程或目标事件修订变化，不能把旧表单覆盖到新工程。

整体或成员注释修改/清空均可 Undo/Redo。规范化后内容与当前值相同则视为空操作，不新增历史记录或制造未保存状态。提交成功后，画布说明视图按当前工程数据刷新，保存状态和源码过期状态同步更新；只改注释不得重建全工程事件引用索引。离开管理界面时按既有未提交草稿规则处理，不静默丢弃或偷偷提交另一处草稿。

新建空工程不预置特定 SLG 事件。本项目示例可以显式定义其所用事件，但框架不能内置 command/combat/loot 等业务常量。

### 6.2 业务节点依赖选择器

新增可复用 `EventMultiSelect.vue` 或等价小组件，替换 `CatalogManager.vue` 中 `draft.events` 多行文本及 `lines(draft.events)` 路径。[S9]

要求：

- 选项仅来自当前工程事件注册表，支持按名称、代码名搜索与多选。
- 保存的是 eventIds，不是名称；选中项展示名称及代码名，可取消单个依赖。
- 没有事件时显示“尚未定义事件，请先进入事件枚举管理”，提供管理入口。
- 不允许自由文本提交、输入回车建事件、allow-create、自造隐藏选项或“其他事件”。
- 引用事件改显示名后标签自动更新；改代码名后及时更新提示。选择器/节点属性若展示注释，必须读取注册表中的同一 `description`，不能复制到业务定义或节点实例中形成过期副本。
- 节点属性面板显示其绑定定义的事件，提供“编辑业务定义”入口；不要伪装成当前节点独享的配置。
- 保留 `ParameterDraft.enumText` 和参数枚举的原功能；不能把通用枚举文本输入一起删除。
- 清理旧表单缓存、定义签名、复制/同步逻辑中的 events 字段，避免保存时把旧事件格式带回工程。

固定说明文案建议：

> **事件依赖**  
> 从工程统一定义的事件中选择。宿主更新业务状态后使用对应枚举通知，行为树只重新评估受影响的节点。此配置属于业务定义，所有绑定该定义的节点共用。

## 7. 画布左上角半透明常驻事件面板

### 7.1 组件与布局

新增 `web/src/EventOverlay.vue`，固定在画布容器左上角，而不是页面左上角，也不是行为树节点坐标系中。

利用现有 Vue Flow 支持的固定面板布局或画布包装容器绝对定位接入；面板不随节点平移缩放。不需要添加拖动能力或第三方窗口系统。

建议样式边界：距画布上/左边缘约 12px，宽约 260px，列表有最大高度和内部滚动。窄窗口下限制宽度，不能遮住全部画布或让折叠按钮不可点击。

背景半透明，文字和按钮保持正常不透明度；不要直接给整块容器设置低 opacity，导致正文也看不清。颜色、边框与图标沿用现有编辑器风格；磨砂效果要有无滤镜时的可读背景，不叠加大面积昂贵效果。

面板点击、滚轮、输入和折叠操作不得传播成画布拖动、缩放、框选、删除节点。面板外区域仍可正常操作画布。管理对话框、菜单等需要更高层级，面板不能盖住它们。

### 7.2 展开/收起与内容

默认展开，无事件时也保留标题、“枚举说明”和“管理”入口。收起后保留一条可展开的标题栏，仍能点击“枚举说明”查看整体功能注释；不允许完全消失到无处恢复。

展开内容包括：标题“事件”、数量、标题栏“枚举说明”按钮、搜索框、“管理”按钮，以及全部工程事件。每行展示显示名称、CodeName、“本树节点数 / 全工程节点数”和独立“注释”按钮。未引用事件照常显示 0，不隐藏；未填写注释的查看入口也不隐藏，点击后展示空状态。窄窗口可将“管理”放入既有菜单，但折叠与“枚举说明”入口始终可达。

折叠状态、搜索文本、当前高亮事件及注释查看目标/浮层开关属于编辑器视图状态：不进入工程 JSON，不增加撤销记录，不让工程显示未保存，不影响生成摘要。可保留在当前页面会话，切换工程时重置高亮和搜索并关闭说明浮层。**注释正文则必须保存在工程中**，不能因为查看状态属于 UI 数据而把正文一起排除。

### 7.3 点击高亮的精确定义

1. 点击事件行主体（名称/代码名/计数对应的主按钮）后设为当前高亮事件；再次点击同一行主体取消；点击另一行主体切换。行内“注释”按钮不触发本条，具体见 §7.6。
2. 高亮当前树中满足以下条件的节点：node.type 是 action 或 condition，node.binding 指向的定义中包含当前 eventId。
3. 高亮必须独立于 Vue Flow 的 selected 状态。不能通过“选中所有节点”冒充高亮，避免用户按 Delete 时误删匹配节点。
4. 不自动改变视口，不重新布局，不自动打开节点属性面板；用户仍可继续选择和编辑节点。
5. 保留选中描边、校验错误、运行状态等已有显示，用额外环线/徽标表达事件匹配，不覆盖已有错误标记。
6. 切换到同工程的另一棵树，保留当前事件，更新匹配节点；没有匹配时显示“当前树没有引用此事件的节点”。
7. 折叠面板不清除当前高亮；标题栏显示当前筛选并保留清除按钮。Esc 仅在没有更高优先级对话框、菜单或注释浮层占用时清除事件高亮；注释浮层打开时，本次 Esc 只关闭浮层。
8. 切换工程、删除当前事件，或恢复的工程中不再存在当前 ID 时清除高亮，不能残留旧节点样式。
9. 标签变化、定义事件变化、节点 binding 变化、新增/复制/删除节点、删除树、撤销/重做后高亮和数量同步更新。
10. 包含当前树内尚未连接的草稿节点，因为它们仍拥有配置。不会因为无法通过完整树结构校验就从引用结果消失。

“拥有事件”只按直接绑定定义判定。父组合节点、SubTree 调用节点不会因为后代监听就自动算直接引用。被引用树内的节点可切到对应树查看；全工程计数按原始画布节点计算，不把运行时展开实例数量当成编辑节点数。

### 7.4 引用索引与性能

新增独立的 `eventRegistry.ts` / `EventRegistryIndex`，避免把注册表和统计逻辑继续堆在大型 App.vue 中。

至少维护或复用以下索引：

```text
eventByID:         EventID -> EventDefinition
definitionByID:    DefinitionID -> Definition
eventToDefs:       EventID -> Set<DefinitionID>
definitionToNodes: DefinitionID -> Map<TreeID, Set<NodeID>>
```

为当前选中事件构建当前树的匹配 NodeID Set，节点样式判断使用 Set.has。节点计数可在相同索引上缓存；同一对 TreeID/NodeID 只统计一次，不重复计算同定义重复配置。

TreeID 与 NodeID 必须采用嵌套 map 或现有无歧义组合键工具，不能直接拼一个可能碰撞的斜杠字符串；不同树里同名 NodeID 不得串联高亮。

工程加载、整体替换和快照恢复时允许一次重建；定义/节点编辑按现有事务机制增量更新，或在单次批量事务后有界重建。节点移动、画布缩放、鼠标悬浮、面板开关、注释查看及仅注释编辑不能触发全工程引用重建，不添加定时轮询或全工程 deep watch。整体说明直接读取工程字段，成员说明通过 eventByID 查找；元数据刷新与引用拓扑修订分开，不能把任何注释改动都当成订阅变更。

索引查询成本应与匹配定义/节点数相关。不要宣称整个 Vue 渲染能做到 O(1)：匹配结果生成和实际节点渲染有其必要成本；要求避免无关树、无关定义的重复扫描。

### 7.5 无障碍与画布导出

事件行主按钮和两类注释按钮均支持键盘聚焦、Enter/Space；主按钮提供高亮选中状态，折叠按钮提供 aria-expanded，搜索有可访问标签。注释按钮使用明确名称（如“查看枚举功能注释”“查看命令变化的事件项注释”）、aria-expanded 和 aria-controls。通过关闭按钮或 Esc 关闭浮层后恢复焦点到触发按钮；按钮已不存在时回到画布事件标题栏。因点击外部关闭时尊重用户新点击目标的焦点，不再强行抢回。

检查现有 `canvasExport`。默认导出的树图不包含管理面板、搜索框、注释查看浮层等工具 UI，也不包含临时事件筛选造成的变淡/高亮；导出期间不能永久改动界面或工程。复用现有导出过滤机制，必要时新增工具层排除标记并测试。使用 Teleport 的浮层也须验证不会意外出现在导出结果中；导出后原有高亮与说明查看状态不被永久清除。

### 7.6 点击查看两类注释：交互与状态合同

新增 `web/src/EventCommentPopover.vue` 或等价的共享只读浮层，由 EventOverlay 调用。画布事件面板共用一个说明实例；不为每个事件预建一个隐藏浮层，也不复用依赖节点锚点的节点注释状态。可以复用已有浮层定位/关闭基础设施。

| 点击目标 | 展示内容 | 不得产生的副作用 |
| --- | --- | --- |
| 标题栏“枚举说明” | 标题“枚举功能注释”，正文为 `Project.eventEnumDescription`。 | 不折叠面板，不切换高亮，不改变真实节点选区。 |
| 某事件行“注释” | 事件显示名、完整 Go 常量名，以及“事件项注释”正文 `description`；稳定 ID 可只读显示。 | 不执行该行的高亮切换，不修改定义、引用、视口或工程内容。 |
| 事件行主体 | 只按 §7.3 切换节点高亮。 | 不自动把打开的说明切换到此事件，也不把“正在查看的事件”当作“正在高亮的事件”。 |

说明可以固定停留供阅读和复制，不能只有鼠标悬浮时可见。点击同一注释按钮切换开关，点击另一注释按钮替换共享浮层的查看目标；提供明确的关闭按钮和 Esc 关闭。点击浮层外部可关闭；外部点击检测须排除当前触发按钮，避免先关闭又被同一次点击重新打开。只有注释控件内部需要隔离画布事件，正常画布点击不能被全屏透明遮罩吞掉。

视图状态建议为：

```ts
// 只存查看目标，不缓存注释正文；每次从当前工程/索引取值。
type EventCommentTarget =
  | { kind: "enum" }
  | { kind: "member"; eventId: string }
  | null;
```

`commentTarget` 与用于事件高亮的 `highlightedEventId`（状态名为实施示意）完全独立：例如 A 事件正在高亮时，查看 B 的注释仍保持 A 高亮。成员行采用“主按钮 + 注释按钮”同级结构，不嵌套 button；注释按钮的 pointerdown、click 以及键盘操作不能冒泡触发行主体或画布快捷键。

**呈现与空状态。** 使用普通文本插值并保留换行（例如 `white-space: pre-wrap; overflow-wrap: anywhere`）；不使用 `v-html`、HTML 注入或执行型 Markdown。正文过长时在浮层内部滚动，可选择/复制完整内容；不要把全文只塞进浏览器 title。没有整体注释时显示“暂未填写枚举功能注释”，没有成员注释时显示“暂未填写此事件项注释”，可提供“去填写”按钮打开管理界面并定位对应区域，不把占位文案写回工程。

**生命周期。** 修改注释、名称、代码名或 Undo/Redo 后，尚在查看的目标按当前工程内容刷新。删除正在查看的成员、切换工程或恢复后目标不存在时关闭浮层；Undo 恢复被删成员不自动重新打开浮层。面板收起或搜索隐藏行导致成员按钮消失时关闭成员浮层；标题栏入口仍在时可以继续查看整体说明。同工程切树可保留查看目标，但必须重新确认当前按钮锚点，失去锚点时关闭，不挂在旧 DOM 上。

**定位与事件优先级。** 浮层定位在按钮附近并限制在可见视口内，避开裁剪容器；窗口变化、列表内部滚动后跟随有效锚点或安全关闭，不轮询位置。用非模态带标题的说明面板表达，而非阻断整个画布的模态框。焦点位于说明内容时，滚动、复制、Delete/Backspace 和 Esc 不得触发删除节点或清空高亮；更高层管理对话框/菜单优先处理，关闭一个层级不能连带关闭或修改其他状态。

注释浮层的打开、关闭、切换目标、滚动及复制均不提交工程事务，不增加撤销步骤，不标记待保存，不使源码过期，也不重建事件引用索引。

## 8. 删除事件：全工程、原子、可撤销

### 8.1 删除确认

允许删除正在被引用的事件，但先显示确认：

> 删除“命令变化”（EventCommandChanged）？  
> 将从整个工程的 N 个业务定义、M 棵树的 K 个节点中清除该事件依赖。不会删除节点、业务定义或业务代码。该操作可撤销。

N 统计引用该事件的定义，包括未被画布使用的定义；K 统计通过绑定继承该事件的画布节点。引用统计使用索引，确认时再次核对当前工程身份和事件修订，不能用过期对话框删除另一个工程的对象。

### 8.2 单次事务

按以下顺序在候选状态或既有原子事务中完成，成功后才统一发布界面修订：

1. 捕获现有工程快照，复用当前撤销/重做机制。
2. 从所有引用该 ID 的 `Definition.eventIds` 中移除该项，包括其他树会使用的定义和未使用定义。
3. 从 `Project.events` 中删除该事件定义及其成员注释；其余事件 ID 不变，`Project.eventEnumDescription` 不变，即使删除的是最后一个事件。
4. 更新注册表/引用索引，清理当前高亮和相关临时 UI；若注释浮层正在查看该成员则关闭，查看其他成员或整体说明则不受影响。正在编辑的相关表单作废或同步清理。
5. 重新校验事件注册表和所有定义引用，保证没有悬空 ID。
6. 一次性提交工程修改，标记待保存，失效生成源码/骨架/校验快照，重新计算相关数量。

失败时不提交；Undo 一次恢复事件、原成员注释及全部引用，Redo 一次再次删除。整体注释不随成员删除而丢失。不能要求用户撤销 N 次才能恢复 N 个定义，也不能只恢复事件却丢掉注释。

不得删除节点或定义，不改变 Node.binding、参数、树结构、布局、业务代码名以及其他事件依赖。不自动替换成另一个事件，不增加通配事件，不加入轮询“补救”。

若清除后某个节点没有任何事件或字段依赖，应在结果提示/说明中明确：它不再因被删事件重评。这是删除依赖的真实影响，不应伪装成“业务行为完全不变”。

### 8.3 防止被旧草稿或异步结果重新写回来

这是必测边界：用户打开业务定义编辑表单后删除事件，旧表单不能再次把已删除 eventId 写回。

提交表单、导入预览和生成结果时验证工程身份/修订；事件删除让相关旧请求失效。即使前端遗漏，也必须由后端事件引用校验拒绝，不接受“先存进去，下次生成再说”。

不要清空历史栈来逃避一致性问题；旧事件通过显式 Undo 回来是合法恢复，与旧表单意外复活不同。

### 8.4 编辑与运行生效边界

级联清理立即作用于编辑工程。用户已有运行实例不会被网页编辑直接修改；需要保存、重新生成、构建并按既有流程发布新 Program 才影响运行时。删除元数据后，手写 Go 中引用已删常量的地方由编译暴露并需要修改。

## 9. 导入、导出、复制与业务定义同步

事件统一管理后，业务目录仅携带 eventIds 不足以在新工程中独立导入。此处必须一起改造，不能保留一个能产生悬空 ID 的旁路。[S5][S11]

### 9.1 新目录交换格式

用带事件定义的自包含对象替代旧 `Definition[]` 数组：

```json
{
  "kind": "behaviortree.catalog",
  "schemaVersion": 3,
  "eventEnumDescription": "用于本工程 AI 对宿主业务状态变化的重新评估。\n先更新权威业务状态，再 Notify；异步完成仍使用 Complete。",
  "events": [
    {
      "id": "7d65e20a9143bc01",
      "name": "命令变化",
      "codeName": "CommandChanged",
      "description": "宿主更新玩家命令及目标后通知；用于重新评估分支。\n例如：玩家从采集切换为移动；本事件不携带异步完成结果。"
    }
  ],
  "catalog": [
    {
      "id": "has_move_command",
      "name": "存在移动命令",
      "kind": "condition",
      "goName": "HasMoveCommand",
      "params": [],
      "eventIds": ["7d65e20a9143bc01"]
    }
  ]
}
```

导出只携带实际导出的定义所引用的事件，每个事件一次，并完整保留各自的 `description`；导出的 ID 与原工程相同。整体 `eventEnumDescription` 作为交换包级元数据携带一次，不复制到每个成员上；它描述来源工程的事件约定，不表示交换包包含来源工程的全部事件。无事件时也有 `events: []`，非空整体注释仍可携带。空注释按 §3.5 省略；事件定义只在事件注册表或此显式交换包里出现，不能根据 eventIds 自动推导出新事件。

旧数组格式和旧 Definition.events 明确拒绝，并提示使用新事件枚举格式重新导出。不得借“目录导入”偷偷做旧事件兼容。

同步修改 `model.ExportCatalog` 的入参，使其能访问工程事件表，例如改为接收 Project；导出只校验目录与事件相关内容，不要求用户草稿树已完成。同步更新 CLI catalog 命令、`/api/catalog`、`catalogTransfer.ts`、`catalog.ts`、`CatalogManager.vue`、复制和下载入口。

### 9.2 冲突规则

| 冲突 | 处理 |
| --- | --- |
| 同 ID、全部事件定义一致 | 复用已有事件，不重复创建。 |
| 同 ID、名称/代码名/成员注释有变化 | 在预览中逐项显示差异，要求明确保留现有或采用导入定义；仅注释不同也不能静默覆盖或重复建事件。后者可能影响已有引用，必须展示影响。 |
| 整体枚举功能注释不同 | 作为独立的工程级差异显示，默认保留当前整体注释；只有用户明确选择“采用导入的整体注释”才更新。导入缺省/空注释不得自动清空现有内容，不自动拼接两份说明。 |
| 不同 ID、同代码名 | 明确提示冲突。用户可选择将导入引用映射到现有事件，或显式修改导入事件代码名后作为新事件导入；不得静默按名字合并。 |
| 导入定义引用交换包未声明的 ID | 拒绝整个交换包，定位具体定义和 ID；不“补建事件”。 |
| 合并后出现 Go 符号冲突 | 拒绝提交，保留预览供修改。 |
| 工程/事件表在异步预览后发生变化 | 旧预览失效，重新校验，不覆盖新的状态。 |

处理业务定义的 keep/replace 冲突后，只导入最终采纳定义实际需要的新增事件及其成员注释。不要因为被用户放弃的定义而留下无意导入的事件。

整体注释冲突和成员冲突分别选择：选择采用某成员不意味着覆盖当前工程的整体功能注释。对规范化后相同的注释不制造冲突；缺省与空字符串视为相同。没有实际采纳任何定义或事件变更时，不顺带应用导入整体注释，也不创建空事务；需要单独改整体注释时使用管理入口。用户明确选择以空整体注释替换非空内容时，预览必须写明“将清空整体注释”。

事件及成员注释、用户明确采纳的整体注释、业务定义、现有节点参数同步以及引用索引作为同一事务提交；Undo 一次恢复全部，包括两类注释。保留既有目录/标签组织规则，不把它们混入事件运行语义。

### 9.3 节点复制和其他输入入口

检查工程 JSON 导入、文件读取、目录复制、定义编辑、节点复制/粘贴、示例加载、服务端保存、预览和生成所有入口。当前工程内复制节点保留 binding 与其继承的事件身份，不重新分配事件 ID。

若现有跨工程复制节点会携带业务定义，其事件依赖也必须经过上述显式交换/映射规则。不能通过剪贴板创建未知事件；未实现跨工程能力的路径不得伪装成功，应明确拒绝缺失定义或事件。

“新增建议”是拟建文件名，可因本地组织调整；现有文件应先定位具体符号再修改。不要仅机械替换字段名而忽略调用链。

## 11. 推荐执行顺序与阶段交付

### 阶段 A：现状确认与合同落地

读取本地约定，记录 `git status --short`、当前提交、Go/Node/npm 版本。搜索所有字符串事件、Definition.Events 和 Program.Dependencies 的引用，形成实际修改清单。确认本地没有另一套未合并的事件实现，保留用户已有修改。

### 阶段 B：运行时与生成器闭环

实现 typed Program、prepareProgram 和 Notify；更新手写 Program 测试。再更新生成器和生成编译测试，验证枚举常量可以实际用于宿主 Notify，字符串调用真实编译失败，未知数值不唤醒节点。

此阶段必须解决未引用事件的合法性、两个依赖表的深拷贝、子树展开依赖，以及整体/成员注释安全生成和版本摘要，不能拖到 UI 完成后再补。

### 阶段 C：输入/交换链路

更新后端、CLI、前端模型、新建工程与示例；实现新目录交换包及冲突/映射规则，完整保留双层注释并单独处理整体说明冲突。确保没有某个入口仍接受旧事件字段，且未连完的树仍可保存合法事件草稿。

### 阶段 D：管理页、选择器和删除事务

实现事件管理、整体功能注释和成员字段注释编辑、受控多选、全工程删除和 Undo/Redo。优先完成事件索引与事务测试，再接 UI。处理旧表单、旧导入预览和生成结果失效，防止被删事件或旧注释复活。

### 阶段 E：画布面板

接入左上角固定半透明面板、搜索、折叠、高亮和统计，并完成标题栏整体注释入口、每行成员注释入口与共享说明浮层；验证查看说明不切换高亮、Esc 只关闭当前层、长文本可读，且不截获无关画布交互、不改变真实选区，不把 UI 状态写入工程。

### 阶段 F：全量测试、示例更新和二进制验收

更新所有仓库维护的正向示例和文档，重新生成产物。完成下面测试清单、前端生产构建和 Go 构建。必须运行新二进制进行编辑器验收，不以 Vite 页面截图代替最终验证。

## 附录 A. 业务事件命名示例

以下仅供已有部队/怪物业务示例参考，不是框架内置事件清单，也不是要求新建工程自动创建这些事件。

| 枚举代码名 | 生成常量名 | 显示名称 |
| --- | --- | --- |
| CommandChanged | EventCommandChanged | 命令变化 |
| ControlChanged | EventControlChanged | 控制状态变化 |
| CombatChanged | EventCombatChanged | 战斗状态变化 |
| PerceptionChanged | EventPerceptionChanged | 感知变化 |
| MovementChanged | EventMovementChanged | 移动状态变化 |
| ResourceChanged | EventResourceChanged | 资源状态变化 |
| LootChanged | EventLootChanged | 掉落物状态变化 |
| InteractionChanged | EventInteractionChanged | 交互状态变化 |
| PatrolChanged | EventPatrolChanged | 巡逻状态变化 |

整体“枚举功能注释”示例：

> 用于本工程 AI 对宿主业务状态变化的重新评估。先更新权威业务状态，再发送对应 Notify；同一时段的通知可能合并，不应依赖每次调用都执行一次业务动作。异步操作完成使用 CallbackToken + Complete。

`CommandChanged` 的“事件项注释（字段注释）”示例：

> 玩家更新当前命令或切换目标后发出。调用前先更新部队的命令类型与目标；例如由采集切换到移动。本事件提示条件重新判断，不直接表示移动、采集或拾取已经完成。

成员注释应明确“哪些真实状态变化后发出”，不能只重复显示名称；整体注释描述共同约定，不替代每个成员的用途说明。异步到达/拾取完成继续走 CallbackToken + Complete，不另外加入 MovementArrived 替代完成回调。
